# Haversine 2.0.0-beta.1 — Candidate Release Notes

**Status: CANDIDATE — NOT TAGGED, STAGED, OR PUBLISHED.**  
**Prepared:** 2026-10-16  
**Expected npm dist-tag on approved staged publication:** `next`.  
**Current public npm stable (`latest`):** `1.6.0`.  
**Last independently verified public V2:** `2.0.0-alpha.1`.

## Purpose

This beta candidate packages all accepted post-alpha compatibility fixes into one reviewed, publishable V2 prerelease. It does not introduce a new public API, runtime dependency, repository, scheduler or service.

## Differences from the immutable published alpha.1

- **Consistent `nearest()` validation:** malformed origin is rejected even for an empty candidate array; invalid `unit` or `radius` options are rejected for empty collections, while a valid empty input continues to return `undefined`. Nonempty semantics and first-candidate tie behavior remain unchanged.
- **Browser geolocation:** a missing, null or incomplete `navigator.geolocation` provider is recognized as unavailable rather than treated as a working browser API; native success and permission errors are forwarded.
- **Release/migration guidance:** public `./browser` and `./legacy` subpaths and the published alpha are described accurately. npm `latest` still denotes stable V1 until separately authorized stable V2.
- **Developer tooling:** TypeScript 7.0.2 is now the library's authoring/compiler baseline, and the Nuxt packed-package fixture uses a pinned compatible npm version to avoid a reproduced npm CLI installer crash. These changes do not modify the V2 public runtime API.

## Preserved package contracts

- Pure `distance()` and `nearest()` APIs with explicit coordinate/unit validation and full numeric precision.
- V1-compatible default facade during the V2 migration line, including historical rounding.
- Explicit `./browser` and `./legacy` package entrypoints.
- Dual ESM/CJS outputs, TypeScript declaration paths and zero runtime dependencies.
- Spherical mean-Earth-radius default (not WGS84 ellipsoidal geodesic distance).

6. **Maintainer action required:** approve a concrete reviewed release SHA, create/verify `v2.0.0-beta.1` tag, review notes, manually run existing `Stage npm Release` with `confirm_publish=PUBLISH` and complete required npm/2FA authorization.
7. **After actual publication:** verify the public `2.0.0-beta.1` artifact through independently installed Node CJS, ESM and TypeScript consumers and npm provenance/signatures; verify its GitHub prerelease and correct `next` dist-tag. Only then mark the beta task DONE.

## Known scope limits

- Absence of open alpha regression issues is **not** proof of zero unreported customer defects. Public beta is the next feedback phase.
- The historical immutable `alpha.1` package retains its already documented boundary behavior; these changes do not rewrite that tarball.
- The validated Chrome fixture does not establish specific Safari/Firefox support.
- TypeScript 7 programmatic compiler API consumers (including some editor/Vue tooling) have not been comprehensively certified by the Nuxt production bundle.
- Stable `2.0.0` and `latest` publication remain **NOT AUTHORIZED**; the existing npm stage workflow explicitly rejects stable versions.
