## Changes since beta.1
- Include accepted [PR #175](https://github.com/DaniilSydorenko/haversine-geolocation/pull/175): exact zero spherical `distance()` for two coordinates at the same North or South Pole, even with differing longitude. No near-pole snapping, no changed public API or default radius.
- Preserve beta.1 strict coordinate, unit and radius validation, including `nearest()` empty-candidate behavior.
- Preserve Node/SSR-safe ESM and CJS exports, TypeScript declarations, `./browser`, `./legacy`, deprecated default V1-compatible facade and zero runtime dependencies.
- Correct pre-stable documentation that still described publicly released beta as an unshipped alpha.

2. On accepted `master`, manually run **Validate npm Release Candidate** with input `2.0.0-rc.1`; it modifies temporary workspace only, no tag/publish.
3. Owner separately authorizes immutable `v2.0.0-rc.1` tag at reviewed commit and GitHub **prerelease**.
4. Owner separately runs manual **Stage npm Release** with `tag=v2.0.0-rc.1`, `confirm_publish=PUBLISH`, then reviews staged content and approves via npm 2FA.
5. After public RC, independently verify real registry CJS/ESM/TS installs, `next` tag and provenance/signatures; leave V1 `latest` unchanged.
6. Review RC hardening and migration evidence. Stable `2.0.0` and `latest` require **another explicit maintainer approval and a separately reviewed workflow change**; current staging refuses stable versions.
